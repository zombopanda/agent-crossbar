# Agent Crossbar v0.4.0

Agent Crossbar v0.4.0 delivers a provider-neutral delegation surface with
explicit model selection, owner-mediated permissions, and truthful job
lifecycle reporting across local providers.

## Public contract

- The MCP surface remains exactly eight provider-neutral tools. The public
  `agent_start` request is intentionally minimal and requires an explicit
  discovered `model`; profiles never choose a silent default or expose
  provider-only fields.
- Model and capability lists come from live provider discovery. Stable error
  codes and the provider-neutral tool contract are part of the compatibility
  promise for clients integrating with Crossbar.
- Local admission, when enabled, accepts only the exact profile/model/task
  candidate returned by the configured policy. It does not rewrite requests or
  select a fallback.
- Maintainer live gates run locally with authenticated provider CLIs; they are
  not part of credential-free public CI.

## Owner-mediated permissions

- ACP permission requests outside the bounded local-edit auto-allow policy stay
  genuinely pending and are surfaced through `job_tail` as a redacted,
  durable `pending_request` with a unique `request_id`, bounded target details,
  and `allow`/`reject` decisions.
- `job_send` resolves a pending request without restarting the ACP coroutine or
  resetting the job deadline. A late or duplicate decision is rejected and can
  never resurrect a terminal job.
- `job_tail` exposes the concrete pending request, including the full redacted
  Claude question while Claude is awaiting input. OpenCode local-target
  extraction recognizes both `filepath`/`parentDir` and their snake_case forms.
- Job ownership is checked before provider stop or permission operations, so a
  client cannot act on another client's job.

## Claude interactive lifecycle

- Claude runs through its native interactive background lifecycle. Claude
  `agent_start` calls must pass `interactive=true`; non-interactive requests
  fail before readiness, admission, lease, or job creation.
- The monitor remains attached while a job is `awaiting_input`, and resumes the
  same provider turn after `job_send`. Repeated `done` readings, echoed input,
  and stale transcript markers are not mistaken for completion.
- The profile advertises only the interactive mode, while the existing
  subscription-backed Claude Code runtime remains the billing boundary.

## Truthful completion and cleanup

- ACP completion is gated on the native `stop_reason`: refusal,
  `max_turn_requests`, cancellation, and token exhaustion are reported as
  failed rather than as successful completed jobs.
- Timeout, rejection, cancellation, and watchdog paths settle pending requests
  in the same terminal operation. Provider work is stopped or reaped under one
  monotonic deadline, and `job_tail`/`job_result` retain the lifecycle evidence
  needed to distinguish waiting, failure, and completion.
- Quiet output, absent workspace diffs, and repeated provider status alone are
  never treated as proof of a stall or successful completion. ACP heartbeats and
  event sequencing keep logs observable without changing the public contract.

## Security and packaging hardening

- Context, diagnostics, command targets, and permission details are bounded,
  redacted, and checked for real-path containment; symlinked and out-of-scope
  paths fail closed.
- Provider adapters remain isolated behind the common interface. Public
  artifacts exclude internal state, telemetry, tests, credentials, private
  paths, and development-only files, while the npm package remains a
  logic-free `uvx` launcher.

## Compatibility notes

The Claude interactive requirement is a deliberate breaking behavior change:
callers that relied on an omitted or false `interactive` value must opt into
the native interactive lifecycle explicitly. The eight-tool surface,
provider-neutral request shape, required model selection, and documented error
code meanings remain the stability boundary; provider-specific discovery and
transport details stay internal.

See the [README](../../README.md) for installation, the support matrix, and the
complete contract.
